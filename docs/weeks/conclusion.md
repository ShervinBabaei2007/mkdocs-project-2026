# Conclusion: Full Process Reflection

> **Summary:** This page pulls together the full arc of the PNWX redesign project - from selecting a broken website to delivering tested, high-fidelity wireframes. It reflects on the key decisions made at each stage, how they built on each other, and what this process means for future design and development work.

---

## The Project in Brief

Over the course of this term, I took [Pacific Northwest X-Ray Inc.](https://www.pnwx.com/) - a medical imaging supplier with a cluttered, hard-to-navigate website - through a complete UX redesign process. The work covered:

- Site selection and rationale (Week 1)
- Usability principles and competitive market research (Week 2)
- User personas, stories, and scenarios (Week 3)
- Problem definition, ideation, and information architecture (Week 4)
- User flows and low-fidelity wireframes (Week 7/8)
- Usability testing on low-fidelity wireframes (Week 10)
- High-fidelity wireframes with visual design rationale (Week 11/12)

---

## How Each Stage Built on the Last

The project was most effective when earlier decisions constrained later ones in useful ways. A few examples:

**Personas → IA → Wireframes.** Dr. Sarah and Mike weren't abstract stand-ins - their specific needs (spec sheet downloads, visible pricing, minimal steps) directly shaped the information architecture, which in turn shaped the wireframe layouts. By Week 7/8, the structure of each page had a clear justification rooted in user behavior, not intuition.

**IA → Testing → High-Fidelity.** Because the low-fidelity wireframes were built on a tested sitemap, the usability testing in Week 10 found labeling problems rather than structural ones. That's a much cheaper category of fix. The high-fidelity wireframes in Week 11/12 could therefore focus entirely on visual design rather than revisiting layout.

**Heuristics → Visual Decisions.** Using three Nielsen Norman heuristics as a filter for every color and typography choice kept the visual design purposeful. The three-color system isn't an aesthetic preference - it's a direct response to PNWX's failure to assign consistent roles to visual elements.

---

## Key Design Decisions & Their Outcomes

| Decision | Rationale | Outcome |
| --- | --- | --- |
| Consolidated navigation labels | IA research: existing labels used internal jargon | Users navigated category pages without hesitation in testing |
| Search bar above the fold | User scenarios: experienced users arrive with a specific product in mind | Reduced reliance on browsing for task-oriented users |
| Price and CTA above fold on product pages | Mike persona: budget-conscious, non-technical | Eliminated the need to scroll before making a purchase decision |
| Three-color system with green CTAs only | Heuristic #4 (Consistency): original site had 6+ competing accent colors | Visual hierarchy is clear; action points are unambiguous |
| Filter panel on category pages | Dr. Sarah persona: needs to narrow by specification quickly | Reduced the click depth to reach a specific product |

## What I Would Do Differently

If I were starting over, I would conduct **real user interviews** rather than building personas from assumptions. The personas I created are plausible, but testing them against actual medical professionals or practice managers would have sharpened the scenarios significantly and might have surfaced needs that weren't obvious from the outside.

I would also **test on mobile earlier**. The scope definition in Week 4 acknowledged mobile as a consideration, but the wireframes were desktop-first throughout. A parallel mobile flow would have surfaced layout compromises that are easier to resolve before high-fidelity work begins.

---

## Applying This Process Going Forward

This term established a working sequence that I'll carry forward into other projects:

1. Define the user and the problem before touching any design tool.
2. Let the information architecture drive the wireframe structure - not the other way around.
3. Test at the lowest fidelity possible before adding visual complexity.
4. Anchor visual decisions to usability principles so they're defensible, not just appealing.

As a portfolio piece, this project demonstrates the full UX documentation process from problem definition through tested high-fidelity wireframes. The PNWX redesign isn't finished - a prototype, accessibility audit, and developer handoff would be the natural next steps - but the foundation built here is solid enough to build on.
